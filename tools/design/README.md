# 图标制作与发布规范

适用：新增或修订的苹果风格纯图标，三种形状一起验收。主体设计、主体比例、外底板分别控制。电视直接使用成品，不执行识图、自动裁边或新的合成操作。

## 1. 生成透明主体

生成模型只绘制应用标识、动物、字母或器物及其材质，不绘制图标外底板。电视、盒子、蜂蜜罐等属于主体本身的造型保留。优先参考官方标识，保持已经确认的识别元素和配色。

- 提供 1024–4096 px 的正方形透明 PNG 前景母稿，宽高均不小于 1024 px。不能把低清小图放大充数；导出器不放大核心主体。
- 每款提供矩形和方形两种构图；同一份方形前景用于圆角方形和圆形。两种构图可以引用同一份前景，但必须一起检查。
- 前景不带外底板、整张不透明背景、内嵌圆角白板或大面积外发光。主体、半透明投影和光照保持独立于底色；透明边缘应完整。
- 用核心主体的 Alpha ≥192 像素测量有效框，Alpha ≥8 的像素检查投影和边缘裁切。模型产生的外底板即使透明，也属于错误内容，须在对照稿中人工检查。
- 透明或玻璃物体需要在并排稿中检查有效框是否代表真实主体；Alpha 测量不能替代视觉判断。

## 2. 选择确认基准

[baselines.json](baselines.json) 固定六款确认稿及三种形状的核心框，坐标为 `[x0,y0,x1,y1]`，右下边界不包含在框内，投影不计入主体。

| 基准 ID | 应用 | 参考用途 |
| --- | --- | --- |
| `clash` | Clash | 动物与简洁实心符号 |
| `hongguo` | 红果 TV | 品牌标识与不对称图形 |
| `video-warehouse` | 影视仓 | 叠层器物与片库 |
| `honey-video` | 蜂蜜影视 | 圆润器物与玻璃材质 |
| `super-live` | 超级直播 | 电视外壳与内部符号 |
| `newbox` | NewBox | 字母、盒体和透视造型 |

导出时以该基准核心框的最长边和中心定位新主体。不同主题仍需比较视觉重量、留白和识别度，不把同一占比套在所有造型上。

Clash 已确认矩形主体框为 `[180,51,506,349]`（326×298），方形、圆形为 `[62,74,432,412]`（370×338）。这些是本次校准后的成品测量，不能再套用旧本地分层合成的 14% 二次缩放规则。

相对基准，核心最长边偏差超过 5%，或中心偏移超过画布对应边的 2%，必须在登记时填写偏差复核原因。超过画布或固定轮廓裁切的主体及投影直接拒绝，不能用复核说明放行。

## 3. 使用固定导出器

在仓库根目录启动本地只读网页服务：

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8080/tools/export.html`，选择 [example.json](example.json) 格式的配方及其中引用的透明 PNG。图像只在浏览器处理，不上传至服务。也可使用 [在线导出器](https://beatsad.github.io/quiet-tv-icons/tools/export.html)。建议每批 6–12 款，以便逐项复核。

配方中的 `reference` 使用上表 ID，`foreground` 为所选文件的文件名。`background` 指定渐变的两个十六进制 sRGB 颜色；`scale` 默认 1，`offset` 默认 `[0,0]`，单位是正式图像素。修改缩放和偏移须检查其在三种形状上的影响。

导出器统一铺满背景，再按六份固定 Alpha 模板写入外轮廓，不让模型决定圆角、外留白或第二层底板。缩略图从未裁切的合成画面生成，再应用自身尺寸的模板，避免黑边和二次蒙版。

| 形状 | 正式图 | 缩略图 |
| --- | --- | --- |
| 圆角矩形 | 720×405 | 320×180 |
| 圆角方形 | 512×512 | 256×256 |
| 圆形 | 512×512 | 256×256 |

下载 ZIP 后解压到新的本地工作目录，再执行（将路径替换为实际目录）：

```sh
python3 tools/design_quality.py finalize --export /absolute/path/to/export
```

该命令验证图像与导出记录，执行无损压缩、更新哈希，产生可独立打开的 `review.html`。每张 PNG 的解码像素在压缩前后必须一致。正式图建议不超过 256 KiB、硬上限 1 MiB；缩略图硬上限 256 KiB。保留 RGBA8、静态、无交错、sRGB，不减色。

## 4. 逐项视觉复核

每批必须查看导出器的并排预览和 `review.html`：

1. 三种形状的核心造型、颜色和材质保持一致，图案有应用识别特征。
2. 与所选确认稿比较底板大小、主体视觉重量和居中；检查是否存在模型画出的第二层底板。
3. 深浅背景下检查边缘、透明区域、发光和阴影，无白边、黑边或光晕残留。
4. 矩形以 314×177、方形和圆形以 176×176 对照，并在矩形 160×90、方形和圆形 96×96 的小尺寸下检查辨识度。这些是验收参考尺寸，不能代替实际电视布局测量。
5. 新材质、明显增加的细节和首次采用的布局，在目标电视抽查上屏效果和加载表现。不得用浏览器或模拟器结果宣称电视性能通过。

主体比例、透明外轮廓之外的颜色、质感和审美由制作人员复核。脚本不会自动识别“苹果风格”或判断好不好看。复核说明应记录真实检查结果，不复制空泛的“已通过”。

## 5. 登记和发布

确认对照稿后，选择从未使用过的资源版本路径，填写本批实际复核结果：

```sh
python3 tools/design_quality.py stage --export /absolute/path/to/export --resource-version 6 --review-note "填写本批实际视觉检查结果"
```

`6` 仅为示例，发布前核对该路径尚未使用。存在比例或中心偏差时，另加 `--deviation-note "说明为何保留该偏差以及检查结果"`。该参数不能豁免裁切、轮廓、尺寸、格式或哈希错误。

`stage` 验证所有条目后，将三形状的正式图和缩略图写到新路径，登记至 [reviews.json](reviews.json)，并在本地导出目录写入 `catalog-items.json`。它不签名、不推送，也不覆盖旧图片。将片段合并至 `catalog.json` 对应条目（新主题还须登记匹配规则），沿用既有 `tools/validate.py sign` 流程递增目录 revision 和签名。匹配规则未改变时不递增规则 revision。

```sh
python3 tools/validate.py verify --root .
```

`verify` 和 `sign` 都会检查新素材的模板 Alpha、前景导出记录、比例与中心、裁切、复核记录、尺寸、格式、体积和哈希。GitHub `Validate` 和 Pages 部署复用同一检查。所有 `images/` 下的新 PNG 都需要登记，不能通过手动复制图片绕过流程。

[legacy-assets.json](legacy-assets.json) 仅登记启用门禁之前的 850 张历史 PNG 及其哈希，允许原字节复用；CI 禁止修改或扩充该豁免表。历史图片不为通过新检查而批量重画、覆盖或删除。基准和模板更新须独立说明原因并重新核对受影响的已登记素材。

已确认的历史成品轮廓标准化使用[裁剪工作台](../crop.html)，在 [normalizations.json](normalizations.json) 单独保存原素材和新素材描述、固定处理参数及复核说明。此路径不重新生成主体、不修改历史原件，也不替代新增透明主体图标的上述检查；生产验证对新成品执行同样的模板 Alpha、尺寸、体积和哈希检查，并验证来源与裁剪几何。

源母稿、配方、并排稿和设备验收资料保留本地；生产 PNG、固定模板、基准参数和发布复核记录进入仓库。模板、导出记录和检查脚本均不进入客户端目录，电视不会额外下载它们。
